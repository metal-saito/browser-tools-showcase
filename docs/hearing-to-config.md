# ヒアリングシートから `CONFIG` を作る手順

`docs/hearing-template.md` に記入してもらった内容を、`estimate/index.html` 先頭の `CONFIG` オブジェクトに落とし込む手順です。
料金表の差し替えはこの `CONFIG` だけで完結します。HTML・計算ロジックは触りません。

```js
const CONFIG = {
  businessName: "…",      // 5-5 店名・屋号
  contactEmail: "…",      // 5-3 問い合わせ先メール
  taxRate: 0.10,
  layouts:   [ { id, label, price } ],
  items:     [ { id, label, price, unit?, maxQty? } ],
  modifiers: [ { id, label, rate? | add? } ],
  areas:     [ { id, label, add } ],
};
```

---

## 1. 「3. 入力してもらうこと」→ どの配列に入れるかの判断表

シートの「3. 入力してもらうこと」の各行を、次の表で振り分けます。

| シートの「選び方」 | その項目の性質 | 入れる先 | 設定するキー | 備考 |
| --- | --- | --- | --- | --- |
| 1 つ選ぶ | 選択肢ごとに**基本料金**が決まる（間取り・プラン・車種など） | `layouts` | `id` `label` `price` | 画面で最初に選ぶ土台の料金。必ず 1 つ選ばれる（先頭が初期値） |
| 1 つ選ぶ | 選択肢ごとに**固定の加算額**が決まる（エリア・距離帯・時間帯など） | `areas` | `id` `label` `add` | 加算なしの選択肢は `add: 0`。先頭が初期値 |
| 複数選べる | 選ぶと**金額が足される**作業・オプション | `items` | `id` `label` `price` | 数量は常に 1 |
| 数を選ぶ | 台数・個数ぶん**掛け算**になる作業・オプション | `items` | `id` `label` `price` `unit` `maxQty` | `maxQty` が上限（例：0〜5 台 → `maxQty: 5`）。0 は「選ばない」で表現する |
| 複数選べる | 選ぶと**割増・割引・加算**になる条件（土日祝・空室・駐車場なしなど） | `modifiers` | `id` `label` と `rate` または `add` | `rate` / `add` の使い分けは次節 |
| 文字を打つ ／ 日付を選ぶ | 金額に影響しない連絡事項（郵便番号・希望日など） | **入れない** | — | 問い合わせ文のテンプレート（`buildInquiry`）側に項目を足す。金額計算に使うなら実装変更が必要 |

判断に迷うときの目安:

- 「必ず 1 つ選ぶ」かつ「それ自体が料金」→ `layouts`
- 「必ず 1 つ選ぶ」かつ「土台の料金に足すだけ」→ `areas`
- 「選ぶか選ばないか」で「作業が増える」→ `items`
- 「選ぶか選ばないか」で「同じ作業の値段が変わる」→ `modifiers`
- `layouts` に相当する項目がない業種（オプションの足し算だけで決まる場合）は、`layouts` を 1 件だけ（例：`{ id: "base", label: "基本料金", price: 0 }`）にすると画面上は実質非表示に近い扱いにできます。見出しごと消したい場合は実装変更になります。

`id` は URL クエリにそのまま使われるため、英数字とハイフンだけで付けてください（例：`2ldk`、`aircon`、`weekend`）。

## 2. 「4-2 割増・割引・加算」→ `rate` か `add` か

| 「どうなる？」 | 「何に対して？」 | 設定 | 例 |
| --- | --- | --- | --- |
| ○% 増し | 基本料金＋作業箇所の合計に対して | `rate: +0.10` | 土日祝 10% 増し → `{ id: "weekend", label: "土日祝の作業", rate: 0.10 }` |
| ○% 引き | 基本料金＋作業箇所の合計に対して | `rate: -0.10` | 空室 10% 引き → `{ id: "vacant", label: "空室（家具なし）", rate: -0.10 }` |
| ＋○円 | 固定で足す | `add: 2000` | 駐車場なし ＋2,000 円 → `{ id: "parking", label: "駐車場なし", add: 2000 }` |
| −○円 | 固定で引く | `add: -1000` | 紹介割 −1,000 円 → `{ id: "referral", label: "ご紹介割引", add: -1000 }` |

現状の実装での `rate` の掛かり先は **「`layouts` の料金 ＋ `items` の合計」のみ** です。`areas` の加算と `add` の固定加算には掛かりません。
シートの「何に対して？」が「出張費にも掛ける」「合計全体に掛ける」などになっている場合は、`CONFIG` だけでは表現できません（次節）。

## 3. 「4-3 細かい確認」→ 現状の実装と違う場合の注意

現状の `estimate/index.html` は次のルールで固定されています。

| 項目 | 現状の実装 |
| --- | --- |
| 消費税 | 税率 10%（`taxRate`）。税込合計を大きく表示し、税抜・消費税を併記 |
| 端数 | 消費税は 1 円未満切り捨て。`rate` による割増・割引額は四捨五入 |
| 割増と割引が両方ついたら | 加算的に適用（＋10% と −10% で ±0）。順番に掛けない |
| `rate` の掛かり先 | 基本料金＋作業箇所の合計のみ |
| 上限・下限 | なし |
| 「要相談」条件 | なし（すべての組み合わせで金額を出す） |

シートの「4-3」の回答がこの表と **1 つでも異なる場合は、`CONFIG` の差し替えでは対応できず、`estimate/index.html` の計算ロジック（`calc()`）の変更が必要です。** 代表例:

- 「税抜で表示」「両方表示」のうち表示だけ変える → 表示部分の軽微な変更（`CONFIG` 外）
- 「四捨五入」「10 円単位に丸める」 → `calc()` の丸め処理の変更
- 「順番に掛ける」 → `calc()` の `rate` 適用順の変更
- 「最低料金 ○円」「○LDK 以上は要相談」 → `calc()` に条件分岐を追加し、結果カードの表示も変更

これらは着手前の確認書に「計算ルールの追加実装」として明記し、見積に含めてください。合意後に判明した場合は、別見積の対象になります。

## 4. 「4-4 検算用の例」→ 完成後の確認チェックリスト

シートの「4-4 検算用の例」を 1 行ずつ URL クエリに直し、完成したページで同じ金額が出ることを確認します。

URL クエリの形式:

```
/estimate/?layout=<layouts の id>&items=<items の id>[:数量],...&mods=<modifiers の id>,...&area=<areas の id>
```

- `items` は `,` 区切り。数量が 2 以上のものは `id:数量`（例：`aircon:2`）
- `mods` は `,` 区切り。該当なしならパラメータごと省略
- `layout` と `area` は省略すると先頭の選択肢になる

チェックリスト（例を記入済み。依頼ごとに 4-4 の行数ぶん追加する）:

| # | 4-4 の条件 | URL クエリ | 期待値（4-4 の「正しい答え」） | 実際の表示 | OK |
| --- | --- | --- | --- | --- | --- |
| 1 | 2LDK＋エアコン 2 台＋キッチン＋浴室、土日祝、近隣市 | `/estimate/?layout=2ldk&items=aircon:2,kitchen,bath&mods=weekend&area=near` | 税込 113,410 円 | | [ ] |
| 2 | | | | | [ ] |
| 3 | | | | | [ ] |

確認手順:

1. `npx serve .` でローカル起動し、上の URL を開く
2. 結果カードの「税込合計」と明細が期待値と一致するか見る
3. 同じ URL をもう一度開き、選択状態（チェック・数量・ラジオ）が復元されているか見る
4. 期待値と一致しない場合は、まず `CONFIG` の金額の転記ミスを疑い、次に「4-3」の回答が現状の実装と異なっていないかを確認する
5. 3 件すべて一致してから、試作 URL を依頼者に送る

参考（例 #1 の内訳）: (38,000 + 24,000 + 15,000 + 14,000) × 1.10 + 3,000 = 103,100 円（税抜）→ 消費税 10,310 円 → 税込 113,410 円
